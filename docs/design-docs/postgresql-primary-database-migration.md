# PostgreSQL 主数据库迁移与生产切换：技术设计

**Author:** Codex  
**Date:** 2026-08-18  
**Status:** DRAFT — 等待生产事实盘点和人工切换授权  
**Reviewers:** 数据库运维、应用负责人、安全负责人、计费负责人

## Context（背景）

项目的主库选择由 `SQL_DSN` 决定：`postgres://` 或 `postgresql://` 使用 PostgreSQL；未配置时使用 SQLite；其余非空 DSN 按 MySQL 打开。`LOG_SQL_DSN` 未配置时复用主库，配置后则成为独立日志库。开发 Compose 使用 PostgreSQL 15，但这仅证明开发配置可连接 PostgreSQL，不能说明运行中的生产库类型、规模、拓扑、备份方式或切换可行。

当前 `model.InitDB()` 的 `migrateDB()` 以 GORM `AutoMigrate` 创建或演进 schema，并包含少量数据回填；它没有历史 SQLite/MySQL 到 PostgreSQL 的复制器。`migrateDBFast()` 并行迁移模型，不保证依赖顺序，不得用于本方案。根项目仍必须继续支持 SQLite、MySQL >= 5.7.8 与 PostgreSQL >= 9.6；本设计只定义一次性将**生产主库**切换到 PostgreSQL 的路径，不删除其他数据库方言。

已有隔离 UAT 只证明：一个清洗后的 SQLite 一致性副本曾导入独立 PostgreSQL、候选应用可在内部网络返回 HTTP 200，且生产容器/卷/网络未被改动。它不证明生产切换、主机端口、完整企业 E2E、MySQL 导入、真实支付/邮件/OAuth/上游调用或回滚。此前的合成清单工具仅校验人工提供的合成 JSON，不能替代真实导入、脱敏或隔离证据。

基线候选曾有 PostgreSQL 的硬门禁：企业账本 `command_summary` 的新写入使用 NUL（`\x00`）拼接，而 PostgreSQL `text/varchar` 不能持久化 NUL。独立 P-M1 修复提交 `df33b9ec9` 已改为无 NUL 的确定性摘要，并在专用隔离 PostgreSQL 库实测通过；该提交尚未整合到最终迁移候选。`enterpriseReferenceHash` 的 NUL 只用于哈希输入、`usedata` 的 NUL 只用于进程内缓存；它们不是同一问题。历史 SQLite/MySQL NUL 账本的专用转换与候选整合后实测仍是带企业表迁入 PostgreSQL 的前置门禁。

## 目标与设计决策

1. 将一个经批准、已冻结写入的 SQLite 或 MySQL 主库完整复制到新的 PostgreSQL 主库，保留业务主键、引用、历史时间和可审计账务数据。
2. 采用**停写切换**，而不是双写、CDC 或在线零停机迁移。当前仓库没有可确认的请求镜像、变更数据捕获、全局维护写闸或跨库一致性协议，不能虚构这些能力。
3. 使用独立的一次性、运营者显式调用的迁移执行器；不得把复制、清洗、序列重置或切换逻辑塞进 `main.go`、应用启动或 `AutoMigrate`。
4. 目标 PostgreSQL 在“开始接受生产写入”前进行结构、数据、序列、业务聚合和受控启动验证；任一门禁失败均不切流。
5. 源库及其可恢复快照在切换后保留只读。开始接受 PostgreSQL 的生产写入后，旧源库不再可直接回切；没有现成的反向同步器。

## Functional Requirements（功能需求）

- FR-1: 迁移执行器 MUST 只接受 SQLite 或 MySQL 作为源主库，并通过实际连接和只读权限确认源类型；目标 MUST 是 PostgreSQL。源/目标数据库标识相同、目标不可写、源可写、或 `LOG_SQL_DSN` 范围未声明时 MUST 拒绝开始。
- FR-2: 执行器 MUST 由人工在受控窗口显式启动，使用只读源凭据和仅限目标库的写入凭据；不得从仓库、日志、迁移报告或命令行回显 DSN、Key、密码、Cookie、邮件或用户正文。
- FR-3: 迁移前 MUST 固化候选应用 Git SHA、源 schema 清单、目标 schema 清单、主库/日志库范围、源数据规模、写入者清单、可用磁盘、备份恢复演练结果和切换联系人。任一事实未知时，生产切换 MUST 停在设计/预演阶段。
- FR-4: 目标 schema MUST 由同一候选应用版本在空的专属 PostgreSQL 数据库中按确定顺序建立，并在加载数据前记录表、列、主键、索引和约束清单。不得对已装载生产数据的目标首次试验未知 DDL。
- FR-5: 执行器 MUST 使用允许表清单逐表复制，不得以“扫描到什么导什么”替代范围控制。它 MUST 保留所有业务主键和 Unix 时间字段，批量写入时检查每列的目标类型、NULL、长度、整数范围、布尔值、UTF-8 和 JSON 有效性；未知表、未知列、越界值、非法 UTF-8、无效 JSON 或 NUL MUST 失败关闭并仅输出表/主键/列定位，不得输出敏感原值。
- FR-6: 迁移 MUST 在所有应用实例、定时任务、异步结算、后台管理写入、支付 webhook、注册/登录写入和上游任务回调均已停止或在入口被可靠拒绝后，获取单一冻结点快照。当前仓库没有可确认的全局写闸；该能力必须由已审阅的运行环境步骤提供，不得仅设置 `NODE_TYPE=slave` 代替。
- FR-7: SQLite 源快照 MUST 使用 SQLite 一致性备份机制并覆盖 WAL/SHM 语义；MySQL 源快照 MUST 先确认存储引擎和一致性方式。不得在仍有写入时只复制一个 SQLite 数据库文件，也不得把 MySQL 的单个导出命令假定为所有表都一致。
- FR-8: 对于每个含自增主键的 PostgreSQL 目标表，执行器 MUST 在导入后按目标最大 ID 重置对应序列，并实际验证下一次 `nextval` 大于该表最大 ID；空表、非标准序列名和无序列表必须显式处理，不得猜测 SQL 标识符。
- FR-9: 验证 MUST 包含所有范围内表的精确行数、主键集合/分批摘要、关键业务聚合、已知引用关系、schema/索引清单和序列检查。关键聚合至少覆盖用户额度、Token 额度、订单金额与状态、订阅状态、主日志与独立日志库范围，以及已启用企业表时的钱包/预留/异常额度和账本累计。任一比较不一致 MUST 销毁或隔离目标并停止切换。
- FR-10: 所有数据库字串载体（普通 `text/varchar`、JSON/TEXT 配置、任务私有数据、Options、日志和账本摘要）MUST 经过 NUL、UTF-8、长度和格式扫描。NUL 不得被静默删除或替换；会改变账务幂等、签名、密钥或 JSON 语义的转换必须另有已批准的专用迁移与回归。
- FR-11: 若 `LOG_SQL_DSN` 为空，日志属于主库迁移范围；若它指向 SQLite/MySQL，日志库 MUST 明确选择“同窗迁入 PostgreSQL”“保留为独立日志库”或“经批准归档”，并分别验证。ClickHouse 日志库不属于本主库复制器，必须保留独立运行/归档决策。
- FR-12: UAT 使用真实生产快照时 MUST 先在隔离 PostgreSQL 恢复，再移除/轮换渠道与 Token Key、SMTP、支付、OAuth/OIDC、2FA、会话、回调地址和真实管理员身份；用户身份改为合成值，仅创建专用 UAT 管理员。UAT MUST 以网络策略阻止生产地址、真实邮件、支付、OAuth 和上游 AI 出站。清洗前后均必须可复核，失败即销毁 UAT 副本。
- FR-13: 影子验证 MUST 是数据影子和受控候选启动验证：源/目标只读比较、合成账户业务回归、候选应用对 PostgreSQL 的内部健康检查与日志审阅。不得镜像真实 API/支付/webhook 流量，因为当前没有无副作用的请求镜像能力。
- FR-14: 切换 MUST 分成两个恢复边界。公开流量开放前，任一失败 MAY 丢弃 PostgreSQL 目标并恢复旧应用/源库；PostgreSQL 一旦接收任何生产写入，旧源库只作只读恢复依据，MUST NOT 直接回切。此后故障按前向修复、受控只读、目标快照恢复和人工账务核对处理。
- FR-15: 切换后 MUST 将 PostgreSQL 设为唯一主写库、清理应用本地缓存并按 Redis keyspace 所有权执行受控失效；不得对共享 Redis 执行无差别 `FLUSH*`。所有原实例必须确认不再连接旧源库，才能解除写入冻结。

## Non-Functional Requirements（非功能需求）

- NFR-1：SQLite、MySQL、PostgreSQL 的正常运行兼容性 MUST 保留；迁移器本身是一次性工具，不修改现有默认 SQLite 回退或 MySQL 分支。
- NFR-2：迁移报告 MUST 只包含版本、数据库类型、表名、行数、聚合值、哈希/校验结论、时间和失败定位；不得包含原始个人数据或 secret。
- NFR-3：所有生产写操作、停机、DNS/代理/DSN 变更、容器重启、备份/恢复和数据库 DDL MUST 有单独人工批准、明确目标和可回退快照。SSH 158 的 UAT 仅能使用确认独立的资源，绝不挂载、替换或重启生产资源。
- NFR-4：迁移窗口、导入吞吐、锁等待和验证耗时 MUST 在至少一次同量级或有据可推导的 UAT 演练中测量；当前没有生产规模数据，故不在本设计伪造 RTO/RPO 数字。
- NFR-5：候选应用必须使用与目标生产一致的加密/会话配置来源，但这些值不得进入 UAT 快照、迁移工件或文档。否则已迁移的渠道等加密字段可能无法读取。

## Acceptance Criteria（验收标准）

### AC-1: 范围与权限拒绝 (FR-1, FR-2, FR-3)

Given 未声明实际源类型、主/日志库范围、源只读授权或目标 PostgreSQL 身份，When 运行预检，Then 不建立写入事务、不创建 schema，并输出缺失事实名称。

### AC-2: 空目标 schema (FR-4)

Given 已批准的候选 SHA 与空的专属 PostgreSQL 数据库，When 运行 schema 初始化，Then 表/列/索引/约束清单被保存为非敏感工件，且与该 SHA 的模型清单一致；对已有数据的首次 DDL 尝试被拒绝。

### AC-3: 冻结快照与导入 (FR-5, FR-6, FR-7)

Given 所有已识别写入者和回调入口均已停写并有冻结时间戳，When 获取 SQLite 或 MySQL 快照并导入，Then 只导入允许表，保留主键和时间字段；任一未知对象、类型/NUL/UTF-8/JSON 错误使目标不可发布。

### AC-4: 序列与数据一致性 (FR-8, FR-9, FR-10, FR-11)

Given 全部允许表已导入，When 运行验证，Then 每表精确行数、主键摘要、关键聚合、引用检查与序列下一值均匹配；所有文本/JSON 载体均有通过的 NUL/编码检查；日志库按预先批准的范围得到独立结论。

### AC-5: UAT 脱敏与数据影子 (FR-12, FR-13)

Given UAT 使用过生产快照，When 导入完成但应用尚未暴露，Then 清洗前后记录显示所有敏感载体已失效或替换、用户为合成身份、仅 UAT Root 可用、出站策略已拒绝真实目的地；候选应用只以合成账户完成 PostgreSQL 回归和内部健康验证。

### AC-6: 切换与恢复边界 (FR-14, FR-15, NFR-3)

Given 全部数据和 UAT 门禁通过且人工批准窗口，When 在公开流量前启动候选实例并切换主库连接，Then 每个实例只连接 PostgreSQL、缓存失效按所有权完成、旧源保持只读；若公开写入前失败，可恢复源库。Given PostgreSQL 已接收生产写入，When 发生故障，Then 不直接改回旧源库，而是进入目标只读/快照/前向修复与人工对账流程。

## Edge Cases（边界情况）

- EC-1: 未发现或无法停止的外部写入者（支付回调、任务轮询、第二个应用实例、直接数据库写入）时，停止在预检；不采用“估计已停写”。
- EC-2: SQLite 存在 WAL、MySQL 存在非事务表、或快照时间点无法证明一致时，停止；不从不一致副本导入。
- EC-3: 导入数据含 NUL、非法 UTF-8、非法 JSON、超出 PostgreSQL `int` 范围或长度上限时，保留源证据并终止。不得自动截断、置零或删行。
- EC-4: 历史企业账本含 NUL 摘要时，等待专用账本兼容修复及其 PostgreSQL 实测；不得用通用文本替换破坏幂等重放。
- EC-5: 目标 schema 启动时 `AutoMigrate` 尝试额外 DDL/回填、索引名不同或唯一约束失败时，停止并在 UAT 重现；不得在切换窗口临时改 schema。
- EC-6: Redis 为共享实例且 keyspace 所有权无法证明时，不执行全库清理；采用应用实例受控重启与已批准的命名空间失效方案，无法实现则停止切流。
- EC-7: PostgreSQL 接受生产写入后发现业务错误时，旧源数据已过期。执行目标库只读保护、保留目标 WAL/快照、根据审计账本前向修复；不以 DSN 回改作为“回滚”。
- EC-8: UAT 脱敏、网络出站拒绝、目标销毁、磁盘加密或访问审计任一项无法证明时，不把真实生产数据复制到 UAT；可继续用全合成数据验证代码。

## API Contracts（API 契约）

N/A — 本设计不新增 HTTP、Relay、支付或管理 API。后续一次性迁移执行器只接受受控的本地 manifest/受管 secret 注入，且不是用户可调用服务；其 CLI/manifest 契约须在实现切片单独评审。

## Data Models（数据模型）

| 对象 | 形态 | 必填约束 | 持久化与敏感性 |
| --- | --- | --- | --- |
| 迁移运行清单 | 一次性非敏感 JSON/签名记录 | 候选 SHA、源/目标类型、表白名单、日志范围、冻结时点、schema 摘要、验证结果 | 不含 DSN、主键值、用户文本或 secret；作为审计工件保留 |
| 表复制规范 | 迁移器内置/版本化清单 | 源/目标表名、列、主键、批次顺序、类型规则 | 只允许候选 SHA 已知模型；未知对象失败 |
| 验证报告 | 一次性非敏感 JSON/文本 | 行数、主键摘要、聚合、序列、引用、NUL/编码、UAT 隔离结论 | 只记录定位与摘要，不记录敏感行内容 |
| 恢复点记录 | 运维受管记录 | 源只读快照 ID、目标初始快照 ID、切流/开放写入时间 | 不进入仓库；用于人工恢复决策 |

现有业务表由候选版本的 `migrateDB()`/`migrateEnterpriseFoundation()` 定义。迁移器不得自行改变业务表模型；字段映射、类型转换和历史账本转换均需单独测试和审阅。

## 实施分片与顺序

1. **P-M0：事实盘点与安全预检设计。** 读取生产环境的数据库类型/版本、表和日志库范围、写入者、备份方式、规模、磁盘、网络、Redis 所有权与外部回调路径；仅只读，缺失即暂停。
2. **P-M1：PostgreSQL 兼容清零。** 整合账本 NUL 修复（当前独立提交 `df33b9ec9`），扫描其他持久化字符串/JSON 与跨方言 SQL；在受控 `new_api_enterprise_test` 上运行 PostgreSQL 模型合同。该分片不复制生产数据。
3. **P-M2：一次性复制器与验证器。** 在独立分支实现经批准的 schema 建立、明确表映射、源只读/目标写入、数据扫描、批量加载、序列重置和验证报告；先以合成 SQLite 与 MySQL fixture 测试。
4. **P-M3：脱敏 UAT 演练。** 在 158 的已确认独立资源上，从一致性生产快照或同量级合成数据恢复，执行扫描/清洗/出站隔离、候选启动和业务合同；删除导入载体并保留非敏感证据。
5. **P-M4：生产切换 Runbook。** 基于测得时长、已批准备份恢复、写入冻结和恢复演练，单独提交具体窗口、责任人、目标数据库、DNS/代理与 DSN 切换步骤。该文档不是 P-M4 的授权。

## Out of Scope（非范围）

- OS-1: 本设计不执行 SSH、UAT 部署、生产备份、数据复制、DDL、DSN 修改、容器重启、流量切换或 PostgreSQL 安装。
- OS-2: 不将 UAT HTTP 200、Compose 默认 PostgreSQL 或合成清单通过描述为生产迁移成功。
- OS-3: 不引入双写、CDC、数据库复制、在线无停机切换、自动回切或新的高可用拓扑；这些需要独立的可靠性设计和运行证据。
- OS-4: 不删除 SQLite/MySQL 支持，不迁移 ClickHouse 日志库，不迁移文件/对象存储，也不假定 `/data` 内容都属于主数据库；附件、上传文件和部署卷需另行盘点。
- OS-5: 不处理支付、SMTP、OAuth、上游 AI 的真实 E2E；UAT 仅用失效凭据与合成账户。
- OS-6: 不以本设计解决企业功能、成员 Key 上限或任何未整合功能切片；这些只作为数据兼容/验收边界。

| 类别 | 当前证据 | 结论 |
| --- | --- | --- |
| 驱动与 schema | `model/main.go` 已使用 GORM PostgreSQL 驱动，`migrateDB()`/`migrateEnterpriseFoundation()` 管理 schema | 支持新 PostgreSQL schema，不等于历史数据复制 |
| 迁移工具 | 仓库没有 SQLite/MySQL→PostgreSQL 数据复制器；已有 `tools/postgres-uat-preflight` 只读合成 manifest | P-M2 尚未实现 |
| UAT | `2026-08-17-postgres-uat-run-result.md` 记录过隔离导入、行数/序列检查和内部 HTTP 200 | 仅为基线 UAT 证据；不能外推到生产或企业 E2E |
| 持久化 NUL | P-M1 独立提交 `df33b9ec9` 已消除新企业账本/用量摘要 NUL，并在 `new_api_enterprise_test` 合同验证通过 | 必须整合到迁移候选；历史 NUL 行仍需专用转换/阻断 |
